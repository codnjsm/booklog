# 게시물은 스냅샷으로 저장하고, 서버가 원본에서 직접 골라 만든다

발행 기능을 만들면서 두 가지를 정했다.

**스냅샷 vs 참조.** 게시물이 원본 `Quote`/`Book`을 참조(`quoteId` 등)만 갖고 있으면, 원본을 나중에 고치거나 지웠을 때 게시물이 따라 바뀌거나 깨진다. "기록과 발행은 분리된 행위"라는 원칙과도 맞지 않는다 — 참조 방식은 게시물이 사실상 원본을 들여다보는 창이 되어, 이후 기록을 고치는 게 이미 공유한 발행물에 영향을 준다. 그래서 발행 시점의 내용을 게시물 문서에 복사해 넣는 스냅샷으로 정했다. 대가는 "발행 후 오타 발견"이 자동으로 안 고쳐진다는 것인데, 좋아요·댓글을 안 쓰기로 했으니 지우고 다시 올려도 부작용이 없다.

**클라이언트가 스냅샷 내용을 직접 못 만들게 한다.** 직전 작업(`friend-visibility-scope`)에서 "친구에게 나가는 데이터는 서버가 필드를 고른다"로 정리했는데, 게시물의 스냅샷도 같은 문제를 갖는다 — 클라이언트가 스냅샷 객체를 만들어 그대로 쓰면, 버그 하나로 독후감 같은 게 스냅샷에 섞여 들어가 친구에게 나갈 수 있다. 그래서 클라이언트는 `{kind, refId, caption}`만 서버에 보내고, 서버(`createPost`)가 관리자 권한으로 작성자 본인의 `reading-notes` 문서에서 `refId`에 해당하는 항목을 찾아 화이트리스트된 필드만 스냅샷으로 만든다. 클라이언트는 "무엇을 올릴지"만 정하고, "스냅샷에 정확히 뭐가 들어가는지"는 서버가 정한다.
